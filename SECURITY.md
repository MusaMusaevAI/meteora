# Безопасность Meteora

Meteora открывает файлы, которые присылают другие люди. Поэтому каждая запись считается **недоверенными входными данными**, и архитектура строится так, чтобы даже вредоносный файл не мог навредить компьютеру или данным.

## Модель угроз

| Кто/что | Возможность | Чего не должно произойти |
|---|---|---|
| Специально испорченный `.webm` | Любые байты, длины, метки времени, вложенность | Выполнение кода, чтение или запись чужих файлов, зависание или падение системы, утечка данных |
| Имя файла | Любые символы, `../`, переводы строк, управляющие символы | Запись вне выбранной пользователем папки, подмена путей, инъекции в Markdown/PDF |
| Другое приложение на Mac | Службы (Services), буфер обмена, открытие файлов | Выполнение действий от имени Meteora без участия пользователя |
| Цепочка сборки | GitHub Actions, токены, зависимости | Утечка секретов, подмена DMG |
| Файл редкого формата (MKV, AVI, WMV, OGG…) | Любые байты в разборщике FFmpeg | Даже при уязвимости в FFmpeg: доступ к другим файлам, сети или данным Meteora |

## Архитектурные решения

**1. Песочница macOS (App Sandbox) и hardened runtime.** Права приложения (`Resources/Meteora.entitlements`):
- читать и писать файлы, которые пользователь сам выбрал (открыл, перетащил, указал при сохранении);
- писать в «Загрузки» (папка `Загрузки/Meteora` для звука, который передаётся в приложение расшифровки);
- закладки с ограниченной областью (`files.bookmarks.app-scope`) — только для журнала встреч: чтобы снова открыть запись, которую пользователь уже открывал сам (закладки только на чтение), для папки пакетной обработки и для папки новых записей встреч, которые пользователь выбрал сам. Закладки хранятся в контейнере приложения и другим программам не доступны. Также — для автопапок: по одной закладке на чтение и запись для каждой папки, которую пользователь сам выбрал в окне выбора папки (см. п. 12);
- микрофон (`device.audio-input`) — только для записи встречи, которую пользователь запускает сам: встроенный микрофон, AirPods, USB-микрофон или iPhone (Continuity). Звук Mac (то, что играют Телемост, Zoom, браузер) записывается через системный «отвод» Core Audio (macOS 14.2+); Meteora при этом себя исключает. Оба доступа macOS запрашивает отдельно и показывает индикатор записи. Файл пишется только в выбранную папку, никуда не отправляется;
- исходящие соединения (`network.client`). Они нужны для двух вещей. Во-первых, WebKit: без этого права macOS завершает процесс отрисовки, и видео не показывается (проверено на CI); для WebKit сеть закрыта тремя независимыми слоями (см. п. 4). Во-вторых, однократная загрузка моделей по кнопке — речи, голосов и модели для итогов (см. п. 8 и 10). Если пользователь сам выбрал облачные итоги и ввёл свой ключ API, текст расшифровки (не звук и не видео) отправляется выбранному провайдеру по HTTPS — только по нажатию «Подвести итоги» и после отдельного подтверждения для каждого провайдера; ключ хранится в связке ключей macOS (только на этом устройстве). Больше приложение в сеть не обращается.

Камера, входящие соединения, Apple Events, JIT и исключения из проверки библиотек не запрошены.

**2. Нет стороннего кода для разбора медиа в самом приложении.** (Редкие форматы разбирает FFmpeg — только в отдельной службе без прав, см. п. 9.) Опасные места любого плеера — демультиплексоры и декодеры.
- Контейнер WebM разбирается собственным парсером на Swift (`WebMDemuxer.swift`). Swift проверяет границы массивов и переполнение чисел, поэтому порча памяти невозможна по построению, а худший исход для испорченного файла — понятная ошибка.
- Звук Opus декодирует системный декодер Apple (AudioToolbox), видео — WebKit. Это компоненты macOS, которые Apple обновляет вместе с системой.
- В самом приложении нет ни ffmpeg, ни других внешних библиотек для разбора медиа. FFmpeg есть только в отдельном изолированном процессе для редких форматов (см. п. 9).

**3. Защитный парсер.**
- Каждая длина проверяется относительно родительского элемента и размера файла, сложение — с контролем переполнения.
- За одно чтение — не больше 64 МБ, вложенность — не больше 8 уровней, пакетов — не больше 30 млн, строки — не длиннее 4 КБ, параметры кодека — не больше 64 КБ.
- Файл не отображается в память (mmap): если флешка или сетевой диск отвалится, будет ошибка чтения, а не падение.
- Обрезанные файлы (частая ситуация с записями) открываются до места обрыва.
- Метки времени вне окна от −1 до +48 часов отбрасываются, разности считаются без риска переполнения. Длительность ограничена 48 часами, дорожек не больше 64, пакетов не больше 8 млн, точек анализа кадров не больше 5000.
- Паузы заполняются тишиной (так звук не расходится с видео), но не больше 10 минут за раз и всего не больше 30 минут или трёх длительностей реального звука. Поэтому «тишиновая бомба» не превратит файл в 150 КБ в сотни гигабайт звука.
- Файл открывается системным вызовом `open(O_NONBLOCK)`, а проверка «это обычный файл» делается уже на открытом дескрипторе (`fstat`). Подмена файла на FIFO или устройство не вызовет зависания.

**4. Изолированный WebKit для видео.**
- Страница плеера встроена в приложение и отдаётся через собственную схему `meteora-media://local/`. Обработчик схемы знает ровно два адреса: `/player.html` и `/media.webm` (открытый файл). Файловая система по URL недоступна.
- Content-Security-Policy запрещает в странице любые скрипты, сеть, фреймы, формы и изображения: `default-src 'none'; script-src 'none'; connect-src 'none'…`.
- JavaScript в содержимом страницы выключен (`allowsContentJavaScript = false`). Код управления плеером выполняется как пользовательский скрипт в отдельном изолированном мире `WKContentWorld("meteora")`. Обработчик сообщений зарегистрирован только в этом мире и принимает сообщения лишь от главного фрейма собственной схемы.
- Навигация разрешена только на страницу плеера, новые окна запрещены, хранилище данных не сохраняется (`nonPersistent`), веб-инспектор выключен.
- Блокировщик содержимого (`WKContentRuleList`) отклоняет любой запрос, кроме `meteora-media://`. Вместе с CSP и политикой навигации это три независимых барьера между страницей и сетью.
- Для анализа кадров приложение само извлекает сжатые кадры из файла и передаёт их декодеру WebKit (WebCodecs) как данные, а не как код. Кадры уменьшаются до 2560 px ещё в WebKit, всего их не больше 300. Если процесс WebKit падает больше двух раз подряд, приложение показывает ошибку, а не перезапускает его бесконечно.
- Заголовок `Range` разбирается строго: только один диапазон, без переполнений, с ответом 416 на всё остальное. Данные передаются частями по 512 КБ и перестают читаться, как только WebKit отменяет запрос.
- Если процесс WebKit упадёт, приложение перезагрузит только страницу плеера.

**5. Файлы и имена.**
- Имена экспортируемых файлов строятся из имени записи с удалением `/ \ : ? % * | " < >`, управляющих символов, переводов строк и невидимых символов направления текста (защита от подмены вида «…gpj.exe»). Длина обрезается до 150 байт.
- Внутри песочницы запись идёт только в выбранный пользователем путь или в `Загрузки/Meteora`. Временные файлы создаются во временной папке приложения и переносятся на место только после успешного завершения, поэтому отменённый экспорт не оставляет битых файлов.
- Распознанный текст попадает в Markdown только внутри блоков кода, тройные обратные кавычки из него нейтрализуются. Имя файла экранируется, поэтому `<img>`, ссылки и картинки из него не превратятся в HTML в Obsidian, Typora и подобных редакторах.
- В Markdown и в тексте для копирования явно указано, что текст распознан со слайдов, а не является инструкцией. Это нужно, если файл вставляют в ИИ-ассистента.
- Уже экспортированный звук используется повторно, только если совпадают путь, размер, время изменения и идентификатор исходного файла. Звук другой встречи с тем же названием не подставится.

**6. Взаимодействие с другими приложениями.**
- Служба Finder «Meteora: передать звук» принимает только файловые URL с расширением `.webm`.
- Перед передачей звука проверяется подпись приложения расшифровки: она должна быть действительной, выданной Apple разработчику (Developer ID или Mac App Store) и совпадать с ожидаемым идентификатором. Приложение-подделка с таким же именем звук не получит.
- Приложение расшифровки запускается через `NSWorkspace` с конкретным файлом. Командная строка и скрипты не используются.
- Буфер обмена заполняется только для этого Mac (`currentHostOnly`), без синхронизации на iPhone и другие устройства.
- Режим самотеста (`--selftest`) включается только переменной окружения CI и недоступен при обычном запуске.

**7. Сборка и распространение.**
- Сборка идёт в GitHub Actions на чистой macOS. Задача сборки и тестов имеет право только на чтение, токен в рабочую копию не сохраняется (`persist-credentials: false`). Право записи есть только у отдельной маленькой задачи на Linux: она не запускает код проекта, а лишь публикует готовый артефакт в ветку `build-output`.
- Используемые actions закреплены по SHA коммита. Во время сборки ничего не скачивается из Homebrew или npm: DMG собирается только штатными утилитами macOS (`hdiutil`, `osascript`, `tiffutil`).
- DMG подписан ad-hoc подписью с hardened runtime. Без платного сертификата Apple нотаризации нет, поэтому macOS один раз попросит подтвердить запуск. SHA-256 образа публикуется рядом с DMG (`Meteora.dmg.sha256`).

**8. Расшифровка речи (GigaAM-v3).**
- Модель скачивается только по явному нажатию «Научить Meteora слушать», только по HTTPS (редиректы на HTTP отклоняются), без cookies и кэша. Источники: Hugging Face, запасной — его зеркало hf-mirror.com.
- **Каждый файл модели проверяется по SHA-256, закреплённому в коде** (`Sources/MeteoraASR/ModelStore.swift`). Хеши сверены с официальным индексом Hugging Face и с фактически скачанными файлами. Файл с несовпадающей суммой удаляется и не используется. Поэтому подменённый сервер или «человек посередине» не подсунут другую модель: это важно, потому что модель разбирает нативная библиотека ONNX Runtime.
- Размер скачиваемого ограничен ожидаемым (+1 КБ): сервер не может забить диск.
- Подсказки распознавателю (термины словаря как hotwords) используют токенизатор той же модели — `tokenizer.model` (255 КБ) из репозитория Сбера `ai-sage/GigaAM-v3` (MIT), URL закреплён на коммите ветки `e2e_rnnt`, SHA-256 закреплён в коде (`SpeechModel.extras`), сверен с LFS-индексом и LFS-указателем Hugging Face. Он скачивается вместе с моделью по той же кнопке (или кнопкой в настройках для уже установленной модели), по тем же правилам. Файл разбирается кодом на Swift с проверкой границ, его фрагменты обязаны совпасть с `tokens.txt` модели; иначе подсказки выключаются.
- Разделение по спикерам использует pyannote segmentation 3.0 (MIT, общая) и одну из двух моделей голоса NVIDIA TitaNet (CC-BY-4.0): «стандартную» TitaNet-S (≈46 МБ вместе с pyannote) или «точную» TitaNet-L (≈107 МБ). Они скачиваются и проверяются точно так же (`Sources/MeteoraASR/SpeakerModelStore.swift`: HTTPS, Hugging Face / hf-mirror.com, SHA-256 из LFS-индекса Hugging Face, сверены с LFS-указателями и с файлами релиза sherpa-onnx), лежат в отдельных папках и удаляются из «Хранилища». Самопроверка CI дополнительно скачивает 14 коротких WAV из github.com/csukuangfj/sr-data по закреплённому коммиту и сверяет их SHA-256.
- Движок (sherpa-onnx v2.0.1 и ONNX Runtime) собран в приложение статически из официального релиза, хеш архива закреплён в `scripts/fetch_vendor.sh`. Во время работы никакой код не скачивается. Детектор речи Silero VAD входит в приложение, его хеш сверен с опубликованным в релизе.
- Распознавание идёт на процессоре Mac. Звук и текст никуда не отправляются. Расшифровки сохраняются в контейнере песочницы и удаляются из окна «Хранилище».

**9. Редкие форматы: изолированный конвертер.** Форматы, которые macOS не открывает сама (MKV, MKA, AVI, WMV, WMA, ASF, FLV, MPEG, VOB, TS/MTS/M2TS, OGV, OGG, OPUS, OGA, AMR, 3GA), преобразуются в MP4/M4A программой FFmpeg. Её разборщики написаны на C, поэтому она работает за тремя стенками:
- **Отдельный процесс.** FFmpeg запускается не в приложении, а в XPC-службе `com.musamusaev.meteora.converter.xpc` внутри `Meteora.app`. Падение или зависание FFmpeg не задевает приложение.
- **Своя песочница без прав.** Права службы (`Resources/MeteoraConverter.entitlements`) — только `app-sandbox`: ни сети, ни выбранных пользователем файлов, ни «Загрузок». Сам `ffmpeg` подписан с `app-sandbox` + `com.apple.security.inherit` (`Resources/ffmpeg.entitlements`) и наследует ровно эту песочницу; без неё macOS его не запустит.
- **Только два дескриптора.** Путь к файлу в службу не передаётся. Приложение само открывает исходный файл (проверяя через `fstat`, что это обычный файл) и создаёт пустой файл в своей временной папке, а по XPC передаёт два файловых дескриптора. FFmpeg читает дескриптор 0 и пишет в дескриптор 1 через протокол `fd:` (`-protocol_whitelist fd`, `-nostdin`) и не открывает никаких путей. Чтение с перемоткой работает, потому что входной дескриптор — обычный файл.
- **Минимальная сборка.** FFmpeg 7.1.5 собирается в CI из исходников (`scripts/build_ffmpeg.sh`): тег проверяется по закреплённому коммиту и SHA-256 всего дерева исходников. Конфигурация `--disable-everything --disable-network --disable-autodetect`, включены только нужные демультиплексоры и декодеры, протоколы только `fd`, `pipe`, `file`; лицензия LGPL, без `--enable-gpl` и `--enable-nonfree`. Скрипт проверяет итоговый файл: только системные библиотеки, только эти три протокола, лицензия LGPL.
- Метаданные, главы и субтитры исходного файла не переносятся. Отмена останавливает FFmpeg (SIGTERM, через 3 с SIGKILL); при закрытии приложения служба тоже останавливает его. Незавершённый результат удаляется.
- Самотест CI проверяет изоляцию на практике: служба и FFmpeg пытаются открыть файл из «Загрузок» и подключиться к сети, и обе попытки должны быть запрещены песочницей.

**10. Резюме встреч (локальная языковая модель).**
- Резюме и заголовок составляет открытая модель Qwen3.5-4B (Apache-2.0, файл GGUF Q4_K_M, 2,7 ГБ) прямо на Mac. Apple Foundation Models русский не поддерживают, а облачные модели исключены: текст встречи никуда не отправляется.
- Модель скачивается один раз по явному действию пользователя по тем же правилам, что и модель речи (п. 8): только HTTPS, редиректы только на HTTPS, без cookies и кэша, размер ограничен ожидаемым. URL закреплён на конкретной ревизии репозитория Hugging Face, а **SHA-256 файла закреплён в коде** (`Sources/MeteoraLLM/SummaryModelStore.swift`). llama.cpp открывает файл только после полной проверки суммы; файл с несовпадающей суммой удаляется. Файл, скачанный пользователем вручную, можно указать приложению — он копируется и проверяется так же.
- Движок llama.cpp (тег b11970) собирается в CI из исходников (`scripts/build_llama.sh`): тег сверяется с закреплённым коммитом и SHA-256 всего дерева, заголовки в `Sources/CLlama/include` должны совпадать с ним побайтно. Собирается только библиотека: без сервера, утилит и сетевого кода (загрузчик llama.cpp не компилируется, скрипт проверяет, что в архиве нет сетевых символов). Библиотека линкуется **статически**: так она подписана вместе с приложением, а проверка библиотек (library validation) остаётся включённой.
- Шейдеры Metal встроены в библиотеку как исходный текст и компилируются системой; права JIT и исполнение неподписанной памяти не нужны и не запрошены. На Intel модель работает на процессоре.
- Расшифровка — недоверенные данные. Она передаётся модели внутри ограничителей, в системной инструкции сказано, что это материал, а не указания. Служебные токены шаблона диалога (`<|im_start|>` и т. п.) в тексте встречи не распознаются: содержимое сообщений токенизируется как обычный текст, поэтому речь или имя файла не могут «подделать» реплику. Ответ модели разбирается как данные (JSON с защитой от обрыва), в Markdown экранируется, ничего из него не выполняется.
- Модель видит только расшифровку, которую пользователь сам попросил обработать. Ответ модели может содержать ошибки, поэтому в экспорт добавляется пометка «составлено автоматически». Модель удаляется из окна «Хранилище».

**11. Облачные итоги: защита персональных данных (Cloud.ru Guardrails).**
- Если для итогов выбран облачный провайдер, по умолчанию включена «Защита персональных данных (Cloud.ru Guardrails)». Перед отправкой строки расшифровки и имена говорящих проверяются **на этом Mac** правилами, перенесёнными на Swift из открытого проекта Cloud.ru [guardrails-llm-filter](https://github.com/cloud-ru-tech/guardrails-llm-filter) v0.1.2 (Apache-2.0; `Sources/MeteoraCore/PIIMasking.swift`): ФИО (полные, с инициалами, имя + фамилия по словарю имён), телефоны РФ, e-mail, СНИЛС, ИНН, ОГРН/ОГРНИП и IBAN с проверкой контрольных сумм, карты (Luhn или слово «карта» рядом), паспорт РФ (рядом со словами «паспорт»/«серия»), КПП, адреса, CVC, пароли, токены, URL с паролем, IPv4. Meteora добавляет 20-значные счета, даты рождения (только рядом с «дата рождения», «г.р.», «родился») и имена, которые пользователь дал говорящим.
- Найденное заменяется метками `<FIO_1>`, `<PHONE_RU_1>`…; провайдер видит только метки. Таблица «метка → значение» живёт в памяти одной операции: никуда не отправляется и не сохраняется. Оригиналы подставляются обратно в готовые итоги уже на Mac; промежуточные заметки длинных встреч остаются с метками.
- Отказ — в закрытую сторону: если правила не собрались или после трёх проходов что-то ещё находится, текст не отправляется, пользователь видит ошибку.
- Сеть и ключ Cloud.ru не нужны. Отдельного облачного API проверки у Cloud.ru нет: upstream — это прокси, который разворачивают у себя; правила на Mac строже — данные не уходят даже в Cloud.ru.
- Ограничения: это правила (regex + контрольные суммы), а не нейросеть. Необычные записи, числа словами, имена без отчества и не из словаря, текст без заглавных букв могут не распознаться; содержание встречи провайдер всё равно видит. Для конфиденциальных встреч — локальная модель.
- Проверка: `Tests/MeteoraCoreTests/PIIMaskingTests.swift` и самотест `PIIGuard.runSelfTest()` (без сети): образцы ПДн скрываются и восстанавливаются, обычные фразы встреч (сроки, суммы, проценты, «3 кв. 2026») не меняются.

**12. Автопапки, фоновая работа, уведомления и вход в систему.**
- **Доступ к папкам.** Песочница не даёт Meteora читать «Документы/Телемост» или iCloud Drive сама по себе. Папку пользователь выбирает в стандартном окне macOS (оно лишь открывается на «Документы/Телемост» как подсказка); после этого Meteora хранит закладку с ограниченной областью (`files.bookmarks.app-scope`, чтение и запись) в своём контейнере (`Application Support/Meteora/autofolders.json`). Доступ открыт, пока папка включена; выключение или удаление папки закрывает доступ и стирает закладку. Других папок Meteora не касается.
- **Что читается и пишется.** Только файлы поддерживаемых форматов прямо в выбранной папке (без вложенных папок); скрытые, временные и недокачанные файлы (`.crdownload`, `.part`, `.download`, `.tmp` и т. п.) пропускаются. Файл обрабатывается, только когда его размер и время изменения не меняются 6 секунд и он открывается на чтение; файлы iCloud, которых ещё нет на Mac, сначала скачиваются системой (`startDownloadingUbiquitousItem`). Каждая запись — те же недоверенные данные, что и при ручном открытии: тот же разборщик, тот же изолированный конвертер. Файлы пишутся только в саму папку или её подпапку «Расшифровки», имена очищаются по правилам п. 5. Сами записи не изменяются и не удаляются.
- **Журнал обработки** (`autofolders-ledger.json`: путь, размер, время изменения, отпечаток SHA-256 первого и последнего мегабайта) хранится в контейнере, чтобы каждый файл обрабатывался один раз; неудачные попытки повторяются не больше двух раз.
- **Итоги и говорящие в фоне** работают только с уже скачанными моделями; модели сами не скачиваются. Облачные итоги в фоне — только если ключ сохранён и пользователь уже подтвердил отправку расшифровок этому провайдеру; иначе шаг пропускается с пометкой.
- **Фоновая работа.** Пока включена хотя бы одна автопапка, закрытие окна не завершает Meteora: в строке меню остаётся значок с состоянием и пунктами «Приостановить автопапки» и «Выйти». Новых прав для этого не нужно.
- **Уведомления** (UserNotifications) запрашиваются один раз, когда добавляется первая автопапка. В уведомлении — название записи, длительность и сохранённые форматы, без текста расшифровки. Нажатие открывает запись в Meteora; другие действия не предусмотрены.
- **Открытие при входе в систему** — через `SMAppService.mainApp`, только если пользователь включил переключатель; macOS показывает Meteora в «Системные настройки → Основные → Объекты входа», там же её можно выключить. Вспомогательных процессов и launchd-агентов нет.

## Как это проверяется

- **Модульные тесты** (`Tests/MeteoraCoreTests`): разбор настоящих по структуре записей (VP8/VP9 + Opus с пакетами по 10 мс, как в Телемосте), потоковых файлов с неизвестной длиной элементов, аудио без видео, неподдерживаемых кодеков.
- **Фаззинг парсера**: 400 файлов со случайными изменёнными байтами и около 150 обрезанных версий. Ни один не должен вызывать падение.
- **Самотест настоящего приложения** в песочнице на macOS: воспроизведение в WebKit, экспорт звука, поиск кадров, распознавание текста, отчёты, загрузка модели с проверкой хешей, расшифровка эталонного русского фрагмента и целой записи, окно хранилища.
- **Самотест автопапок** (`AutoFolderStore.runSelfTest`): временная папка в «Загрузках», запись дописывается по частям 8 секунд; проверяется, что обработка начинается только после того, как файл перестал меняться, что сохраняются выбранные форматы и запись в журнале обработки, и что повторный просмотр папки и копия той же записи не обрабатываются снова.
- **Регрессионные тесты на найденные аудитом атаки**: файл с переполнением меток времени, «тишиновая бомба», вредоносные имена файлов, подмена файла на FIFO.
- **Независимый аудит кода** по методологии [Strix](https://github.com/usestrix/strix) (white-box): модель границ доверия, трассировка данных от входа к опасным операциям, проверка реалистичных сценариев атаки. Сам Strix рассчитан на веб-приложения и требует Docker и ключ к LLM, поэтому для нативного приложения применена его методология, а не автоматический сканер.
