# Безопасность Volant

Volant открывает файлы, которые присылают другие люди. Поэтому каждая запись считается **недоверенными входными данными**, и архитектура строится так, чтобы даже вредоносный файл не мог навредить компьютеру или данным.

## Модель угроз

| Кто/что | Возможность | Чего не должно произойти |
|---|---|---|
| Специально испорченный `.webm` | Любые байты, длины, метки времени, вложенность | Выполнение кода, чтение или запись чужих файлов, зависание или падение системы, утечка данных |
| Имя файла | Любые символы, `../`, переводы строк, управляющие символы | Запись вне выбранной пользователем папки, подмена путей, инъекции в Markdown/PDF |
| Другое приложение на Mac | Службы (Services), буфер обмена, открытие файлов | Выполнение действий от имени Volant без участия пользователя |
| Цепочка сборки | GitHub Actions, токены, зависимости | Утечка секретов, подмена DMG |

## Архитектурные решения

**1. Песочница macOS (App Sandbox) и hardened runtime.** Права приложения (`Resources/Volant.entitlements`):
- читать и писать файлы, которые пользователь сам выбрал (открыл, перетащил, указал при сохранении);
- писать в «Загрузки» (папка `Загрузки/Volant` для звука, который уходит в MacWhisper);
- исходящие соединения (`network.client`). Они нужны для двух вещей. Во-первых, WebKit: без этого права macOS завершает процесс отрисовки, и видео не показывается (проверено на CI); для WebKit сеть закрыта тремя независимыми слоями (см. п. 4). Во-вторых, однократная загрузка модели речи по кнопке (см. п. 8). Больше приложение в сеть не обращается.

Камера, микрофон, входящие соединения, Apple Events, JIT и исключения из проверки библиотек не запрошены.

**2. Нет стороннего кода для разбора медиа.** Опасные места любого плеера — демультиплексоры и декодеры.
- Контейнер WebM разбирается собственным парсером на Swift (`WebMDemuxer.swift`). Swift проверяет границы массивов и переполнение чисел, поэтому порча памяти невозможна по построению, а худший исход для испорченного файла — понятная ошибка.
- Звук Opus декодирует системный декодер Apple (AudioToolbox), видео — WebKit. Это компоненты macOS, которые Apple обновляет вместе с системой.
- Ни ffmpeg, ни других внешних библиотек в приложении нет.

**3. Защитный парсер.**
- Каждая длина проверяется относительно родительского элемента и размера файла, сложение — с контролем переполнения.
- За одно чтение — не больше 64 МБ, вложенность — не больше 8 уровней, пакетов — не больше 30 млн, строки — не длиннее 4 КБ, параметры кодека — не больше 64 КБ.
- Файл не отображается в память (mmap): если флешка или сетевой диск отвалится, будет ошибка чтения, а не падение.
- Обрезанные файлы (частая ситуация с записями) открываются до места обрыва.
- Метки времени вне окна от −1 до +48 часов отбрасываются, разности считаются без риска переполнения. Длительность ограничена 48 часами, дорожек не больше 64, пакетов не больше 8 млн, точек анализа кадров не больше 5000.
- Паузы заполняются тишиной (так звук не расходится с видео), но не больше 10 минут за раз и всего не больше 30 минут или трёх длительностей реального звука. Поэтому «тишиновая бомба» не превратит файл в 150 КБ в сотни гигабайт звука.
- Файл открывается системным вызовом `open(O_NONBLOCK)`, а проверка «это обычный файл» делается уже на открытом дескрипторе (`fstat`). Подмена файла на FIFO или устройство не вызовет зависания.

**4. Изолированный WebKit для видео.**
- Страница плеера встроена в приложение и отдаётся через собственную схему `volant-media://local/`. Обработчик схемы знает ровно два адреса: `/player.html` и `/media.webm` (открытый файл). Файловая система по URL недоступна.
- Content-Security-Policy запрещает в странице любые скрипты, сеть, фреймы, формы и изображения: `default-src 'none'; script-src 'none'; connect-src 'none'…`.
- JavaScript в содержимом страницы выключен (`allowsContentJavaScript = false`). Код управления плеером выполняется как пользовательский скрипт в отдельном изолированном мире `WKContentWorld("volant")`. Обработчик сообщений зарегистрирован только в этом мире и принимает сообщения лишь от главного фрейма собственной схемы.
- Навигация разрешена только на страницу плеера, новые окна запрещены, хранилище данных не сохраняется (`nonPersistent`), веб-инспектор выключен.
- Блокировщик содержимого (`WKContentRuleList`) отклоняет любой запрос, кроме `volant-media://`. Вместе с CSP и политикой навигации это три независимых барьера между страницей и сетью.
- Для анализа кадров приложение само извлекает сжатые кадры из файла и передаёт их декодеру WebKit (WebCodecs) как данные, а не как код. Кадры уменьшаются до 2560 px ещё в WebKit, всего их не больше 300. Если процесс WebKit падает больше двух раз подряд, приложение показывает ошибку, а не перезапускает его бесконечно.
- Заголовок `Range` разбирается строго: только один диапазон, без переполнений, с ответом 416 на всё остальное. Данные передаются частями по 512 КБ и перестают читаться, как только WebKit отменяет запрос.
- Если процесс WebKit упадёт, приложение перезагрузит только страницу плеера.

**5. Файлы и имена.**
- Имена экспортируемых файлов строятся из имени записи с удалением `/ \ : ? % * | " < >`, управляющих символов, переводов строк и невидимых символов направления текста (защита от подмены вида «…gpj.exe»). Длина обрезается до 150 байт.
- Внутри песочницы запись идёт только в выбранный пользователем путь или в `Загрузки/Volant`. Временные файлы создаются во временной папке приложения и переносятся на место только после успешного завершения, поэтому отменённый экспорт не оставляет битых файлов.
- Распознанный текст попадает в Markdown только внутри блоков кода, тройные обратные кавычки из него нейтрализуются. Имя файла экранируется, поэтому `<img>`, ссылки и картинки из него не превратятся в HTML в Obsidian, Typora и подобных редакторах.
- В Markdown и в тексте для копирования явно указано, что текст распознан со слайдов, а не является инструкцией. Это нужно, если файл вставляют в ИИ-ассистента.
- Уже экспортированный звук используется повторно, только если совпадают путь, размер, время изменения и идентификатор исходного файла. Звук другой встречи с тем же названием не подставится.

**6. Взаимодействие с другими приложениями.**
- Служба Finder «Volant: звук в MacWhisper» принимает только файловые URL с расширением `.webm`.
- Перед передачей звука проверяется подпись MacWhisper: она должна быть действительной, выданной Apple разработчику (Developer ID или Mac App Store) и совпадать с ожидаемым идентификатором. Приложение-подделка с таким же именем звук не получит.
- MacWhisper запускается через `NSWorkspace` с конкретным файлом. Командная строка и скрипты не используются.
- Буфер обмена заполняется только для этого Mac (`currentHostOnly`), без синхронизации на iPhone и другие устройства.
- Режим самотеста (`--selftest`) включается только переменной окружения CI и недоступен при обычном запуске.

**7. Сборка и распространение.**
- Сборка идёт в GitHub Actions на чистой macOS. Задача сборки и тестов имеет право только на чтение, токен в рабочую копию не сохраняется (`persist-credentials: false`). Право записи есть только у отдельной маленькой задачи на Linux: она не запускает код проекта, а лишь публикует готовый артефакт в ветку `build-output`.
- Используемые actions закреплены по SHA коммита. Во время сборки ничего не скачивается из Homebrew или npm: DMG собирается только штатными утилитами macOS (`hdiutil`, `osascript`, `tiffutil`).
- DMG подписан ad-hoc подписью с hardened runtime. Без платного сертификата Apple нотаризации нет, поэтому macOS один раз попросит подтвердить запуск. SHA-256 образа публикуется рядом с DMG (`Volant.dmg.sha256`).

**8. Расшифровка речи (GigaAM-v3).**
- Модель скачивается только по явному нажатию «Научить Volant слушать», только по HTTPS (редиректы на HTTP отклоняются), без cookies и кэша. Источники: Hugging Face, запасной — его зеркало hf-mirror.com.
- **Каждый файл модели проверяется по SHA-256, закреплённому в коде** (`Sources/VolantASR/ModelStore.swift`). Хеши сверены с официальным индексом Hugging Face и с фактически скачанными файлами. Файл с несовпадающей суммой удаляется и не используется. Поэтому подменённый сервер или «человек посередине» не подсунут другую модель: это важно, потому что модель разбирает нативная библиотека ONNX Runtime.
- Размер скачиваемого ограничен ожидаемым (+1 КБ): сервер не может забить диск.
- Движок (sherpa-onnx v2.0.1 и ONNX Runtime) собран в приложение статически из официального релиза, хеш архива закреплён в `scripts/fetch_vendor.sh`. Во время работы никакой код не скачивается. Детектор речи Silero VAD входит в приложение, его хеш сверен с опубликованным в релизе.
- Распознавание идёт на процессоре Mac. Звук и текст никуда не отправляются. Расшифровки сохраняются в контейнере песочницы и удаляются из окна «Хранилище».

## Как это проверяется

- **Модульные тесты** (`Tests/VolantCoreTests`): разбор настоящих по структуре записей (VP8/VP9 + Opus с пакетами по 10 мс, как в Телемосте), потоковых файлов с неизвестной длиной элементов, аудио без видео, неподдерживаемых кодеков.
- **Фаззинг парсера**: 400 файлов со случайными изменёнными байтами и около 150 обрезанных версий. Ни один не должен вызывать падение.
- **Самотест настоящего приложения** в песочнице на macOS: воспроизведение в WebKit, экспорт звука, поиск кадров, распознавание текста, отчёты, загрузка модели с проверкой хешей, расшифровка эталонного русского фрагмента и целой записи, окно хранилища.
- **Регрессионные тесты на найденные аудитом атаки**: файл с переполнением меток времени, «тишиновая бомба», вредоносные имена файлов, подмена файла на FIFO.
- **Независимый аудит кода** по методологии [Strix](https://github.com/usestrix/strix) (white-box): модель границ доверия, трассировка данных от входа к опасным операциям, проверка реалистичных сценариев атаки. Сам Strix рассчитан на веб-приложения и требует Docker и ключ к LLM, поэтому для нативного приложения применена его методология, а не автоматический сканер.
